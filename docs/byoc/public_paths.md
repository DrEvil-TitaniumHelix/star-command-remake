# Public tree: path policy (lane byoc-b6, docs/BYOC.md B6; SC-3 = A, SC-4 = A, SC-6 open)

Rule (SC-3 = A): the public tree drops **original bytes and direct extracts** (byte copies, converted tables,
sprite renders / atlas, screenshots, the manual, disassembly with raw bytes, the Microsoft runtime's
disassembly/decompilation). Our pseudocode, specs, ledgers, engine, importer, translators, annotations, tools and
plans stay. Machine-readable form: `tools/byoc/public_filter.txt` (git filter-repo `--paths-from-file`, used with
`--invert-paths`). History check: every path the private history ever had is still in today's tree (2026-10-18),
so the filter covers the history as well; `tools/byoc/leak_scan.py --history` proves it per blob (docs/byoc/B6.md).

## REMOVE

| path | why |
|---|---|
| `game/assets/files/` | 107 byte copies of the game disk (the manifest's hashes) |
| `game/assets/data/` (all, incl. `items.json`, `manual.json`) | tables converted from INFO/NAME/MISSION/MES-n ...; manual.json = manual text |
| `game/assets/atlas.png`, `atlas.json` | every sprite of the banks (atlas.json alone is layout, but pairs with the pixels; the importer rebuilds both) |
| `game/assets/saves/veteran/` (CHARINFO.BAS, CHARNAME, README.md) | CHARINFO.BAS = the shipped blank save + INFO values; README.md quotes item names and mission text. The importer's recipe rebuilds the save (convert/veteran.js) |
| `game/modules/space.js`, `inside.js`, `plbattle.js`, `spbattle.js`, `starport/flow.js` | generated by bas2js (tools/byoc/modules.json `out`): the compiled program transliterated, strings inline. Tier 3 (B3) rebuilds them |
| `game/modules/space/banks.js`, `inside/banks.js` | generated (modules.json `banks_out`) |
| `game/modules/startup.js` | hand-written (STARCOMM/STARTUP have no generator), but it holds the STARTUP string literals byte-exact (title tune, drive/adapter names, menu text). **Gap:** the public game has no STARTUP/STARCOMM module until B3/B4 either generate it at import or move its literals to import-time lookups (by DS offset, MODULE_CONSTANTS.md) |
| `decode/listings/` | disassembly listings with the raw-byte column. **Decision: dropped, not byte-stripped**; they are regenerable on the player's machine from the EXEs (tier 3 qbdis), and a stripped form would still carry every string |
| `decode/data/str/` | .STR stub listings (raw bytes) |
| `decode/data/png/` (559 renders incl. sheets/, hypothesis/) | sprite renders |
| `decode/data/tools/_<MOD>.json`, `_<MOD>_STR.json` | modconst.py dumps: every string-literal INIT record and DATA statement of each module |
| `decode/docs/StarCommand_Manual_SSI1988.pdf`, `.txt` | the SSI manual and its OCR |
| `decode/brun30/funcs/` (740 .c), `decode/brun30/rt_asm.txt` | Ghidra decompilation / disassembly of BRUN30.EXE (Microsoft code) |
| `decode/rea/brun30_strings.json` | strings extracted from BRUN30.EXE |
| `acceptance/**/*.png` (ref, out, integration, veteran) | screenshots of the original (DOSBox) and of the port |
| `acceptance/ref/SU-01.wav` | recording of the original's title tune |
| `acceptance/integration/run2/save/` | CHARINFO.BAS + CHARNAME written by a play-through (derived from the shipped save) |
