# MANUAL_XCHECK — SSI 1988 manual vs decode and build (lane manual-xcheck)

This file checks the game's functions against the manual: every documented function, rule and table value of `decode/docs/StarCommand_Manual_SSI1988.txt` (OCR of the 32-page SSI 1988 rule book; page numbers below are the OCR's `===== PAGE n` markers unless a row says "printed") compared with the decode (`decode/pseudo/<MOD>.bas.md` listing offsets, `SCREENS_INDEX.md`, `CROSSREF.md`, `decode/data/*`, `game/assets/files/INFO.BAS` / `NAME` decoded from MBF) and with the build in `game/` (generated statement-for-statement, so the build was checked at the cited offsets and in the hand-written runtime/fixtures). Checked 2026-10-15 by seven section passes (one per manual chapter) and merged here; two headline discrepancies were re-verified at merge (Esper roll STARPORT 05742/057A2; terrain ±35 PLBATTLE 064C4/06AF9/077A0). Strategy guides: none in `decode/docs/` yet.

Verdicts: **MATCHES**; **DISCREPANCY** (manual and binary differ - the build follows the binary, which is the reproduction target under SC-1 = B); **MANUAL-ONLY** (documented but not in the 7 decoded modules); **BUILD-GAP** (in the binary, missing or wrong in `game/`); the equipment pass adds **NOT LEGIBLE** (OCR row unusable) and **UNRESOLVED** (decode reading uncertain).

## Findings that need someone (summary; details in the rows)

**Build gaps:** none open. The two DEMO rows (A10, H60) are reclassified to the "Undecoded extras" scope decision; the copy-protection row (B43) is a faithful reproduction of the shipped binary (decision below). Every other row that touches the build reproduces the binary at the cited offsets.

**Decisions (manual vs binary; the build follows the binary unless decided otherwise):**
1. Copy-protection words (B42/B43): the manual's numbered sections give 47 of the 50 `RuleWord$` words; the shipped STARPORT.EXE has length-only placeholders, so any lowercase word of the right length passes, in the original and in the build. Keep (faithful) or fill (stricter than the original).
2. DEMO mode (A10, H60, "Undecoded extras"): optional attract mode.
3. Rules where the 1988 binary differs from its own manual (the build keeps the binary behaviour): Esper attribute 0..49 (+5 % 50..52 when no Esper) vs manual 0..60 (A); pay at most 60 days per visit, only after a completed mission (A); main menu option 3 cannot reach "Two Floppy Disk Drives" (A, STARTUP 0073/0D2F); training sessions cause no injuries (B); bankruptcy adds 90,000 to the balance (B, 07BF5); close-range bonus 100/(dist+1) vs "up to 25 %" and movement-menu G/H order (F); terrain ±35 and no cover bonus for the squad, gravity fatigue cubed above 1 g, room door not passable (G); surprise more likely in open rooms, detector blip axes swapped (H); espionage limited to the first four life-form types, cargo trips never meet planet encounters (E); WeaponTable column meanings (C).

**Decode fix requests (doc names/notes, for the crossref fixer):** WeaponTable column labels (C: +54 ROF, +108 magazine, +216 range, +270 damage type, +432 to-hit, +540 intimidation, +594 weapon/skill type); SPBATTLE aim terms are bonuses, Impersonate Deity +40 vs tech < 4, `IsMissile!` inverted (F); ENCINFO c2 = initiative bounds not morale, c7 bribe sign (G); STARPORT save lock after two wrong answers, not three, and the stale "credits set to 90000" / PT-09 render-bug notes (B); SCREENS_INDEX SP-03 cursor 0..15 (E). Room door 097C3/09911 vs 04FA8 (G56) should be re-read from the bytes before anyone treats it as original behaviour.

**DOSBox questions raised by the manual (added to `acceptance/DOSBOX_REQUESTS.md` as D-MX-1/D-MX-2):** D-MX-1 room-fight door exit (G56: can the squad leave an enclosed-room fight through the door the briefing names?); D-MX-2 shield facing for fire from dead ahead (C, the UNRESOLVED row). No existing DOSBox request is settled by the manual: the open ones are geometry/timing/audio questions the rule book does not describe (every section pass checked).

Key findings:
- **Prices**: every price in the appendix is the INFO.BAS base price x `PriceFactor!` 1.2 (STARPORT 076F-0791: PriceMul!(0..2) = 1.2; all buy flows multiply, e.g. 3C92, 4911, 5218). Fourteen cells in 12 personal-weapon rows (6 weapon costs, 8 reload costs) are 1 credit high: the manual rounded x.4 up there, but rounds x.4 down elsewhere. Armor cost per point on ships is the base value with no 1.2 factor (STARPORT 514F; manual 5/12/27.5/50 = ShipTable +81).
- **Column meanings the manual fixes** (they differ from the labels in the STARPORT Arrays table): WeaponTable +216 = RANGE (the p26 range column matches all 54), +270 = DAMAGE TYPE (p27 legend 1 bullet ... 12 laser; matches all 54; Arrays calls it 'shots'), +432 = TO-HIT BONUS (Arrays 'field 7'), +540 = INTIMIDATION FACTOR (Arrays 'field 8'), +594 = WEAPON TYPE / skill (1 heavy arms, 2 light arms, 3 chemical, 4 explosive; Arrays 'field 11'). +54 / +108 are then ROF / magazine capacity (Revolver magazine 6, MiniMAC 50), not 'ammo capacity' / 'accuracy' as the Arrays labels say. GunTable +25 = ROF and +175 = to-hit (both match p28/p29). HandWeaponTable +12 = to-hit BONUS. DefHw has a second 'BONUS' column (movement) that is not stored in INFO.BAS: the code computes it from the type number.

NOT LEGIBLE = the OCR has no usable value for any column of the row. No DISCREPANCY in the data tables is larger than 1 credit except where a lost digit is the more likely explanation (each such case is named in its row).

### Decode-doc notes (task checks with no manual text in this section; not counted as rows)

- ENCINFO c2 "morale thresholds x1.3/x0.7/x0.6" (PLBATTLE.bas.md header, DATA_FILES.md, CROSSREF.md): the code does not use these as morale values. `InitHi!/InitMid!/InitLo! = c2*1.3/0.7/0.6` (01039-01055) are the initiative countdown bounds. The countdown starts at InitHi!+1, jumps to 0 once below InitMid! (06593-0659D), and steps by `InitLo!*(-0.25)` (0657B). Group "morale" is SUB_3D68: a group of more than 4 with 2 alive, or more than 2 with 1 alive, gets `GrpState! = 3` and `GrpTactic! = 5` (flee) (03ECC-03EE8).
- ENCINFO c7 "bribes fail below 4": the code is `Offer! = (C7Mood! < 4) * -40` (0399D). With QB true = -1 this gives +40 when c7 < 4 (all ENCINFO c7 are 1..3 per the variable table) and 0 otherwise. A bribe therefore starts at 40 instead of the usual 50 and is never an automatic fail. PB-07's devjump script even gets "They accept 600 credits as payment for a truce". The header's variable row for Offer! ("-40 for a bribe") makes the same sign mistake. The build matches the binary (plbattle.js 1144 `lt(...) * (-40)`, lt returns -1).
- No BUILD-GAP was found. plbattle.js is a statement-for-statement bas2js output. Every offset cited above was checked in it (00268, 0024B, 022A8, 046AC, 048AA, 055E4, 06486, 064C4, 064CE, 06A8E, 06AF9, 06B40, 07750, 077A0, 07BC3, 0847D, 083A7, 079C5, 01F04, 05D2F, 0A3D4, 0A42C, 0A527, 09911, 097C3, 04FA8, 04761, 01A75, 06D15, 06AAB, 0129A) and carries the same expression. devjump.js only seeds the RNG and types keys.
