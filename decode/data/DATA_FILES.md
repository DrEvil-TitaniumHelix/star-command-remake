# Non-sprite data files: sequential text files and BSAVE'd numeric arrays

Lane: data. Originals: `re-targets/starcommand/starcoma/`, read 2026-10-15. Sprite banks are in `SPRITES.md`, the .STR stubs in `STR_FILES.md`, START.BAT in `BAT.md`. Every claim below names the file, offset and bytes it rests on; "unknown" means exactly that.

## A. Sequential text files (written by BASIC `PRINT #` / `WRITE #`, read by `INPUT #`)

Common format evidence: CR LF line ends (`0d 0a`), a single `1a` (Ctrl-Z) as the very last byte (BASIC's text-mode CLOSE writes it; e.g. ENCINFO 0xAC2 = `1a`, NAME 0x16E5 = `1a`, CHARNAME 0x09 = `1a`). Numbers are printed BASIC-style: a leading space (or `-`) and a trailing space (`20 34 20 20 33 30 20 2d 31 30 30` = " 4  30 -100").

## C. How the game forms file names (for the pseudocode lanes)

- BLOAD/BSAVE without an extension get ".BAS" from the runtime: STARTUP BLOADs `"title"` (0xD2E6, 5 chars) and there is only TITLE.BAS; SPACE/INSIDE/... BLOAD `"CHARINFO"` and only CHARINFO.BAS exists. Confidence H.
- Numbered files are `stem$ + "-" + n$ + ext$` built with RT3F_55 (concat) and RT3D_11/RT3F_71 #80/RT3F_AF (STR$ of an integer, leading space handled somewhere): literals "MAP" (SPACE 0xAEC8), "SPPIC" (SPACE 0xAFF0, STARPORT 0xA9E4), "SHIP" (SPACE 0xA960, SPBATTLE 0x70AE), "ENSHP" (SPBATTLE 0x8BE0), "BIGSH" (PLBATTLE 0xC72E, 0xC738), "INMAP" (INSIDE 0x956C, 0x9576), "MES" (INSIDE 0x9580), "IN" (INSIDE 0x955E), "TR" (PLBATTLE 0xBF88), "-" (SPACE 0xAA12, STARPORT 0xA63C, INSIDE 0x9362, SPBATTLE 0xA6B8), ".BAS" (SPACE 0xA96C, STARPORT 0xA9EE, INSIDE 0x9564, PLBATTLE 0xBF96, SPBATTLE 0x8BEA), ".EGA" (PLBATTLE 0xBF8E only). PLBATTLE has no "-" literal, so TR-n / BIGSH-n are built from "TR"/"BIGSH" plus STR$(-n) (STR$ of a negative number yields "-n" with no leading space) or a variable - the pseudocode lane should confirm.
- A drive prefix variable (literals "A:", "B:", "" in every module) is prepended to every file name; the hard-disk configuration uses "".
