## Defects

- **D1 — INSIDE (owner build-engine, this lane) — FIXED.** INSIDE and PLBATTLE declare COMMON 0x1850..0x802A (module header hw[20]/hw[21]); X!/Y!/OldX!/OldY! and the detector flags (DS 0x4890..0x48AC) are COMMON, and INSIDE keeps X!/Y! after a won fight (0D51 skips the reassignment). The port rendered them as module-locals (reset to 0 on every CHAIN). Fix: bas2js emits `COMMON_VARS`, inside/runtime.js keeps them in `E.commonScalars` (shared, keyed by DS address). The audit (`audit_bload_scalars.py`, second class) shows no other module affected (SPACE/SPBATTLE's extended COMMON is entirely BLOAD regions, PLBATTLE has no scalars there).

## Findings about the original (no port defect)

- **F1 — WITHDRAWN (was a port defect, not the original).** I reported that the rule-book check accepts any character at or above the expected one. The DOSBox reference run (dosbox-ref, qa fix F-5) proved the original rejects `zzz` ("Wrong!"): STARPORT 09C1B-09C26 computes ABS(ASC(typed) - ASC(word)), the decode had rendered the ABS idiom as a plain difference. Fixed by crossref/build-plbattle (starport.js regenerated, new rows PT-09w/PT-09a). Consequence for S1: my saves were accepted only because of that defect; the save file format, the reload and the fresh-profile transfer (S1, S6) remain valid, the "no Wrong!" detail does not.
- **F2 — WITHDRAWN (port behaviour differs from the original).** I reported that the room door cannot be used to flee, based on the decode of SUB_96FC (098E2 loop 4..7 leaves the door cell inaccessible) and the port's beeps. The DOSBox reference run (dosbox-ref, qa fix F-6, D-QA-7 answered) shows the original squad DOES leave through the bottom door and returns to INSIDE at OldX/OldY: the decode's impassable-door reading is wrong somewhere (097C3/09911/04FA8). F-6 is with build-plbattle + the crossref decode fixer; the port defect is theirs, not an original quirk.
- **O1 — squad encumbrance decides combat** (observation, balance): miniguns (weight 18.5) + metallized armor gave carried 61 vs max 21..27 → current move 0 → no command phase at all (only `Movement Phase 3`, no `Command:` lines); after selling the miniguns the squad attacked normally.
