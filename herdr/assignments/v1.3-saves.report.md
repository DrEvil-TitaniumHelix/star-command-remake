## Design and implementation

Added slots.js and slots.test.mjs. installEscape installs slots automatically, so engine.js and STARTUP need no edits. Named slots are unlimited in count subject to browser storage quota. Names have a 24-character limit. New names create slots; selecting an existing slot edits its name and Enter saves/overwrites that name. The UI explicitly labels the overwrite behavior. Autosave is reserved and replaced on every actual STARPORT arrival.

Each snapshot contains CHARINFO.BAS, CHARNAME, all seven shipped IN-n.BAS and INMAP-n.BAS station pairs, every additional saved station/map file discovered in memory or localStorage, and LOGBOOK when present. Snapshots copy bytes at capture time. Storage uses a separate starcommand:slots:v1 JSON record, preserving the existing current-disk format. Slots survive the prepared-save loader's files.reset(), which only removes starcommand:file:* keys. Storage read failures are caught; absent storage permits session-only slots. Write/quota failures surface in the picker and do not report a successful slot save.

The existing Esc arrival checkpoint drives Autosave. The currentModule setter captures arrival exactly once; the redundant pre-CHAIN entry capture was removed. Autosave does not write the live COMMON or current disk. SaveLock is cleared in captured bytes by the existing captureSave policy, with its decoded source cited in the overlay.

Esc S-Save & Quit opens a slot picker when saveSlots is enabled. New named slot opens a name editor; existing names can be selected, edited, and overwritten. Arrows, Enter/Space, Esc/B and clicks work in the picker; the name editor accepts printable characters, Backspace, Enter and Esc. Enter is required to confirm a name (Space remains a valid name character). Long lists scroll with selection. Esc L-Load opens the load picker. The original R/S/Q and Settings paths remain available.

On STARTUP/STARCOMM, the input wrapper intercepts 1 only while the printed 1-Play Star Command menu is visible and slots exist. This pauses the existing game through the Esc gate and shows the picker before choice 1 can continue. Continue current disk passes choice 1 through once; Back cancels to the menu. Loading installs the entire selected disk file set and removes saved station files/LOGBOOK absent from the slot, then restarts through an engine ChainSignal('STARCOMM') with fresh opts. The signal is raised at the next game input poll or resumed timer boundary, inside the engine's run loop. No browser reload is needed, so memory-only disk files also remain usable. The previous picker is dismissed and the old pause gate is released.

Classic mode or saveSlots=false bypasses all slot interaction, hides L, and retains the original single-disk S-Save & Quit path. Settings stays intact. Idle/Classic paths draw no slot overlay.

## LOGBOOK policy

captureSave now copies LOGBOOK beside COMMON and names. Live starport menu saves use the live journal; menu/arrival/departure rollback uses that checkpoint's journal. A first-write journal entry also covers LOGBOOK for disk-fallback rollback. Missing journal files are removed rather than inheriting another voyage's log. Slots capture the resulting current disk after the Esc save/rollback policy runs. The panels lane can keep writing LOGBOOK exclusively through E.files without further integration changes. Restarting STARCOMM also clears obsolete Esc departure checkpoints and the write journal.

## Protection settings review fix

E.options.protection assignments and initial protection=true are session overrides only. They never call Settings.set or change persisted noChallenge. Classic still always enables the original challenge, even after an explicit false override. Toggling noChallenge in Settings clears the override and immediately applies the player's switch.

## README text to merge

**v1.3 named saves (slots.js).** With Named save slots enabled, Esc S asks for a named slot before saving and quitting; choose New named slot or an existing slot, then confirm the name with Enter. Saving the same name overwrites it. Esc L loads a slot, replacing the current disk's crew, station maps and journal and restarting at STARCOMM. On the title menu, 1-Play opens the same picker when slots exist; Continue current disk uses the original current save and Esc/B cancels. Autosave records each STARPORT arrival separately. Each slot includes CHARINFO.BAS, CHARNAME, all station/map files and LOGBOOK when present. Preferences and named slots are stored locally; slots remain usable for the current session without storage, and quota failures are displayed. Classic mode uses the original single save with no slot picker or autosave. The ?save=<name>[&force=1] prepared-save loader remains compatible.

## Review fixes

- **F-4:** the title picker appears once per title visit, including when cancelled. Successful slot loading marks the ensuing STARCOMM visit as already selected; the next 1 continues with the loaded disk. A later visit can offer the picker again. Unit tests cover cancellation, Continue current disk, loading, and a fresh visit. The browser regression now loads a slot, restarts STARCOMM, presses 1, and asserts STARPORT with no modal.
- **F-3 regression:** port journal A is saved; a voyage adds a battle entry; return-to-port checkpoint followed by Quit without saving leaves LOGBOOK A on disk. Save & Quit away from port writes the departure checkpoint's A. These tests use an in-memory checkpoint journal, exercising captureSave without any checkpoint disk write.
- **Names:** shared validateSlotName runs in the picker before its save callback and again at the start of the Esc save path, before any CHARINFO/CHARNAME/LOGBOOK/map write. Empty names and reserved Autosave are rejected. Regression tests count zero disk writes and compare CHARINFO bytes after each invalid submission.
- **Dev jumps:** STARPORT arrival autosave is suppressed for the entire session while the URL contains a screen parameter. A regression verifies that fixture arrivals do not replace an existing player's Autosave.
- **Compact storage:** file bytes are base64 strings in separate per-slot records, with a small name/key index retained at starcommand:slots:v1. Old inline JSON-array records still load and migrate on the next successful save. Normal arrivals serialize/write only the new Autosave record and the index, leaving all other slot records untouched. Regression tests exercise legacy loading/migration and assert exactly two storage writes per subsequent autosave.
- **Quota:** failed storage writes show “Storage full; free space and retry” in the picker. Uncommitted new records are cleaned up, the previous index and in-memory slot list are preserved, and the old overwritten record is removed only after the new index succeeds. This provides the requested clear quota message rather than assuming a fixed browser capacity. Quota failure is covered by a storage stub regression.
