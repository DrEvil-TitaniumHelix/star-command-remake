## Implementation

Pointer targets are derived on each click/hover in 320x200 logical coordinates, with CSS scaling handled through the canvas rectangle. Clicks call `input.device(key)`; modals receive only `modal.click(x,y)`. Hover changes the native cursor without drawing. `window.__clickRegions()` exposes current disjoint regions.

Printed letter/digit labels, Y/N cells, uppercase ENTER/SPACEBAR/SPACE/function-key/control words, numbered options, live arrow crosses, and map cells are supported. A map click sends one horizontal-first arrow step; clicking the cursor cell does nothing. INSIDE uses COMMON scalar positions, SPACE uses G cursor fields, and PLBATTLE uses the landed `E.moduleInstance` seam (`GrpX!(5)-26`, `GrpY!(5)-5`). PB-04 grid targets are active; no export is outstanding.

Live sprite tracking preserves original PUT behavior and checks XOR erasure, module identity, and current framebuffer pixels before publishing arrow regions. No framebuffer changes occur without mouse input.

IN-10 shows one current option, so adjacent rows step Up/Down and ENTER accepts. `#n` retains the original pointer implementation's digit mapping; IN-10 itself uses arrows/ENTER rather than direct option-number selection.

## README text for build-engine2 to merge

Mouse: click a printed hotkey label, an active crew picker choice, a Y/N letter, an uppercase ENTER/SPACE word, or an arrow-cross arm to send its keyboard key. Click a map cell to take one arrow step toward it (horizontal first), including the PLBATTLE grid. Click above/below the current IN-10 option to step through choices. The native cursor indicates targets and follows canvas CSS scaling. Esc modal clicks go exclusively to the overlay. Pointer input adds no framebuffer drawing.

## Review fixes

M-1: label spans stop before comma, period, semicolon, colon, double-space gaps, subsequent selectors, or uppercase control words. `B-Buy the Ship, ENTER to Exit` has a 14-cell B label and separate five-cell CR word. Overlaps are resolved by original rectangle area, smallest first, before subtracting covered pieces; word and Y/N cells therefore beat enclosing labels. The input menu detector's broad fallback spans are deliberately not reintroduced.

M-2: `X>`/`X)` selectors require an explicit current picker prompt. Evidence: SPACE 040A3/040C3 (SP-05 change positions/with whom), 06E84 (inspect); SPBATTLE 02F93 (fix), 03F48/03F68 (switch); STARPORT 0387A (buy), 054DD (dismiss), 06285/062A5 (switch), 071E6 (clone), 084B4 (inspect); INSIDE 031F5 (fire), 035CF/035EF (switch), 041C1 (inspect), 05985 (change); PLBATTLE 04FE1 (weapon switch). These exact visible prompts gate the tags. Passive SP-00/SP-01, SB-02, PB-04, and PT-02 rosters get no selector regions, consistent with SCREENS_INDEX's panel keys column. Unit tests cover a passive SP-01-like panel and the active weapon picker.

M-3: a preceding dash is accepted on the weapon chart identified by its printed `-G-Bullet` and `-J-Laser` lines. STARPORT 03A70/03AA2/03ACE/03B86 print G/B/J/F; 03BCC permits A..L (`CmdMax! = 12`). Other screens do not acquire dash-prefixed chart targets.

Control words match uppercase only, so `Enter a single word` is prose. Printed ranges such as `A-K to change` and `A-D  1-5 to retarget` create no single-key regions; they require keyboard selection of an individual member of the range.

The harness now requires identical screenshot pixels except for explicitly listed animated screens SB-02 (ship/galaxy sprites) and PB-04 (portraits). Those may pass with identical text rows and are reported separately. `screen:keys` arguments replay real keyboard navigation after the dev jump on every fresh load; this exercises the ship browser and all 12 weapon chart targets without module edits. Artifacts are saved outside the repository under `%TEMP%/v11fix-mouse*`.
