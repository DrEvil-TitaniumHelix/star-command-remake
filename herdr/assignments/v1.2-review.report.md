## 1. Control overlay (help.js): PASS, with defects H-1..H-3

The content is built every frame from `E.pointer.regions()` + `screenText()`, as required. SU-03, PT-02, PT-04, SP-01, IN-02, IN-10 and PB-04 list exactly the printed hotkeys (menu labels, Y/N, ENTER words, picker selectors, arrows/map). No key appears in help that the screen does not take. Classic mode and the controlOverlay setting hide both the panel and the `?` button.

- **H-1 (medium, spec gap): keys the screen accepts but does not print are missing.**
  - Every STARPORT `Select Option` / `Select A ...` menu goes through SUB_22C4 (STARPORT 02346), which always accepts ENTER (Cmd! = -51) and SPACE (-32).
  - Scenario: PT-04 "Arsenal" accepts ENTER (back) but help shows only `A/B/C`. The same holds for the weapon-class menu at 03BE6.
  - On the SPACE system map (marker provider) and the INSIDE "Use arrow keys to pick" picker, no arrow sprite is live, so help prints only "Click a cell: step toward it" and never "Arrow keys".
  - The owner asked for "every hotkey the screen accepts". The cause is that pointer regions carry only printed keys. Fix: add implicit-key entries per module (pointer.js or a small help table), or state the limit in the README.
- **H-2 (minor): help stays on top of the Esc overlay and cannot be closed there.**
  - help.js:52-59 does not check `E.input.modal`. While modal, input.js:78 sends F1 / pad Back to `modal.key`, which ignores them.
  - Scenario: F1, then Esc on PT-02 → the help panel covers the top-right of the Esc box (verified screenshot). F1 does nothing until the menu is resumed, yet the panel itself says "F1: this help".
  - Fix: skip drawing while `E.input.modal` is set.
- **H-3 (minor): in Classic mode gamepad Back is dead.**
  - help.js:37 sets `onDeviceHelp` unconditionally, so input.js:186 maps Back to F1 → `toggle()` → `open()` refuses.
  - Verified with `?classic=1`: Back neither queues a key nor opens the Esc overlay.
  - v1.1 (and the README before this change) had Back = Esc. Fix: `BACK: this.onDeviceHelp && settings.on('controlOverlay') ? F1 : ESC`, or make the hook return false when it is disabled.

## 2. Map zoom (zoom.js + engine.js wrap): FAIL (Z-1)

What works:
- The wheel zooms around the pointer and RMB zooms out.
- Arrow steps on SP-01, IN-02 and PB-04 keep the zoom.
- Esc resets the zoom to 1 (verified).
- A screen with no map resets it.
- Classic mode or mapZoom off means wheel and zoomAt do nothing (verified).
- The click → `viewToLogical` path is correct.
- The engine.js highlight transform `scale(s); translate(-2ox,-2oy)` maps logical L to `2s(L-ox)`, the same as `present()`.

Defects:
- **Z-1 (high): the view stays zoomed on non-map sub-screens of SPACE and INSIDE.**
  - zoom.js:16-17 treats "a `map` region exists" as "this is a map screen". The SPACE long-range provider (pointer.js:68) and the INSIDE provider (pointer.js:61) only check that the arrow sprite is still live, and the EQUIPING list is printed over the map area without erasing the arrow.
  - Scenario 1: SP-01, zoom 2x at (60,60), press `E` → `E.zoom.level` is still 2 on the EQUIPING list. The screenshot shows the list cut off; the `A-`/`B-` selectors and "A-K to change" are off-screen.
  - Scenario 2: IN-02 + `E` behaves the same (level stays 2 on "EQUIPING").
  - The same false map regions also cover the list text for v1.1 clicks: clicking non-selector list text sends an arrow key. This is a pointer.js issue.
  - Fix: make the providers require the map content, e.g. no `EQUIPING` / list header, or the frame/marker pixels, or have zoom reset on any `screenText` change outside the map area.
- **Z-2 (minor): the context menu is suppressed everywhere, including Classic mode and non-map screens** (zoom.js:51; verified `defaultPrevented` with `?classic=1`). The assignment says that elsewhere clicks behave as in v1.1. Fix: guard it with `active()`.
- **Z-3 (deviation, documented):** The owner's "LMB click = zoom in on that spot" and "double-click" are not implemented anywhere. Zoom-in is wheel-only, so a mouse without a wheel cannot zoom in. This is acceptable only if the owner agrees; the report documents it.

## 3. Item tooltips (items.py / items.json / tooltip.js): FAIL (T-1..T-4)

The raw data is correct (see Method). PT-04 buy lists, the PT-04 ship browser, SP-10 equip, and STARPORT/SPACE crew rows all recognise the right record. The purchase price is ×1.2 in buy lists and the ship price uses INT (05227). Ambiguous names return null; no wrong item was found.

- **T-1 (high, wrong value): "armor points per ton" is the reciprocal.**
  - items.py:13 labels ShipTable +90f "armor points per ton", and the tooltip prints `armor points per ton: 0.005` (Wasp) / `0.008` (Dagger).
  - The game uses this column as tons per armour point: BaseWt = col9 - armor × col90 (02A9C). The Dry Dock prints `"A ton of armor is"; INT(1/col90); "points"` (0508B), i.e. 200 / 124 points.
- **T-2 (high, wrong derived numbers): "base weight" and "cargo capacity" do not match the game.**
  - items.py:45 computes cargo = max wt - col9 and cites SPACE 08194 MaxWt!-BaseWt!. But the game's BaseWt! = INT(col9 - col36 × col90) (STARPORT 02A9C), which SPACE prints as "Base Wt" (772B).
  - Scenario (f32): Dagger shows base 85 / cargo 27, but the game has 84 / 28. Hunter 200/70 vs 190/80. Warrior 210/90 vs 201/99. Ranger 200/66 vs 191/75. Only Wasp and Hornet (0 armour) match.
- **T-3 (medium): raw codes are shown where the decode gives a meaning** (tooltip.js:62-63 prints every field as `key: value`).
  - `damage type: 1`: WeaponTable +270, 1..12. PLBATTLE.bas.md 0xD01A / 08206 gives 6 flame, 7 rocket, 8 explosive, 9 chemical, 10 nuclear, 11 incendiary, and 1-5 / 12 single-target. MANUAL_XCHECK C11/C50 has the legend 1 bullet … 12 laser.
  - `skill type: 2`: +594. PLBATTLE 68BA-6924 gives 1 heavy arms, 2 light arms, 3 chemical weaponry, 4 explosives.
  - Ship `size class: 0` while the same screen prints "Class Scoutship" (ShipSize$ = NAME 38..41).
  - Hand-weapon col 2 is hidden as "unknown field 46", although MANUAL_XCHECK line 213 identifies it as the to-hit bonus.
- **T-4 (medium): ammo price inconsistent with the purchase price.**
  - In buy lists the weapon price is ×1.2, but `ammo price: 3` (5.56mm Palm Gun) is raw. The game charges ammo × PriceFactor (squad 0405E, ship guns 04BCA): 3.6, and the manual's reload cost is 4 (MANUAL_XCHECK C56).
  - On the PT-04 "Ammo for which gun?" list the panel shows `Base price: 17` for the weapon, which is not what is being bought.
- **T-5 (minor): tooltips draw above the Esc overlay.** `at()` (tooltip.js:75) does not check `E.input.modal`. Verified: with the Esc menu open, `at()` returns "Jason" on PT-04, "9mm Revolver" on SP-10 and "Gruber" on SP-01, and the panel is drawn over the paused menu.
- **T-6 (minor, gap vs the owner):** crew *candidates* (recruitment, unnamed) get no tooltip, and the owner's "hits / reloads / weapon slots" are absent. Both are documented as open in the lane report.
