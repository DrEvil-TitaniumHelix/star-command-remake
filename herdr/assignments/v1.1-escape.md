## Behaviour
- `installEscape(E)`: set `E.input.onDeviceEscape = open`. `open()` sets `E.input.modal = { key, click }` and draws the overlay through `E.display.overlays` (canvas 640x400, drawn over the framebuffer, never into it): a centred box with three items `R-Resume`, `S-Save & Quit`, `Q-Quit without saving` in the game's own 8x8 font style (reuse E.text font data or plain canvas text in the EGA palette), plus a one-line note (see Save). Keys: R / Esc / pad B = resume; S = save & quit; Q = quit; arrows + ENTER move/confirm a highlight (gamepad d-pad/A arrive as arrow/ENTER keys). `click(x, y)` (logical 320x200 coords, sent by pointer.js while modal is open) picks the item under the point.
- While open the game is paused: no key reaches it; if feasible pause `E.timer` waits and `E.audio` (document what you did).
- Save & Quit: write the game's own save so that a later start (STARTUP menu, load) continues correctly: CHARINFO.BAS (E.state.save()) + CHARNAME (ship name + crew names, same text format the STARPORT writer produces: read flow.js 09D0C-09D5A and E.data.charName()) + any IN-n/INMAP-n the current module holds unsaved (or state that the module only writes at its own exit). Work out per module (STARPORT, SPACE, INSIDE, SPBATTLE, PLBATTLE, STARTUP) whether the current COMMON state is a consistent save point (a load restarts in the module CROSSREF §1 says, with the state it expects); where it is not (mid-battle, inside a module that only writes back at exit), save the last consistent state instead (e.g. the COMMON snapshot taken when the current module was entered via CHAIN) and show the note `Saved as of <place/when>` on the overlay before quitting. Table per module in the report.
- Quit (both): `window.close()`; if the window is still open after ~300 ms, clear the screen and show `You can close this window.` (the local server may keep running).
