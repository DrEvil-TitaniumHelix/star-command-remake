# v12-help report

Implemented only `game/engine/help.js` and `game/engine/help.test.mjs`; this report is the third owned source file. No commit.

## Design

`installHelp(E)` exposes `E.help = { open, close, toggle, isOpen, lines }` and installs `input.onDeviceHelp`. Help starts closed. Its model reads the live pointer regions and Text screen on every call, including every open display frame. Keys are deduplicated case-insensitively; arrow/map rectangles become one instruction each. Labels come from their printed regions, with selector punctuation removed. Printed ENTER/SPACE instructions retain their surrounding instruction text. Fixed gamepad, mouse, Esc and F1 instructions follow.

The panel uses shared `drawPanel` in `display.overlays`, right-aligned, using scale 1 when scale 2 cannot fit in the right half. No framebuffer writes, modal input, timer changes or game pause. The DOM corner button is a semitransparent 24px square over the bottom-right canvas corner, positioned from its live bounding rectangle. Hover transfers between canvas and button. Disabled controlOverlay/Classic mode hides the button and panel and closes help on the next frame.

## README text to merge

**Control help (v1.2).** Press F1 or gamepad Back, or hover the canvas and click the bottom-right `?`, to toggle current-screen control help. The game continues running and accepting its ordinary controls. Help reads the same live clickable regions as the mouse, showing printed hotkeys, selector names, prompts and map movement alongside gamepad mappings. The panel is drawn above the game picture and starts closed. Settings > Control overlay disables the panel/button; Classic mode disables it as well. Gamepad Back now toggles help; Start opens the Esc menu. Map zoom currently uses the wheel to zoom in/out and right-click to zoom out; clicks on hotkeys/map cells retain their normal action.
