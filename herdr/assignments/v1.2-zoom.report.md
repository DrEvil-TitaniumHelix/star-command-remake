Implemented only game/engine/zoom.js and game/engine/zoom.test.mjs; no commit. Browser artifacts are under acceptance/out/v1.2 (including the requested SP-01-zoom.png, IN-02-zoom.png, PB-04-zoom.png). Other lanes' working files were left untouched.

## Design

Enable only when settings.on('mapZoom'), no input.modal, and pointer.regions() contains kind 'map'. This uses the existing provider's live-screen detection, including the INSIDE arrow-picker provider. No independent module/area heuristics are maintained. The provider cursor's own cell has no map region, but other cells establish that the provider is active.

Steps: 1, 1.5, 2, 3, 4. Display already disables image smoothing. Integer factors have uniform integer pixel replication; 1.5 is nearest-neighbour with uneven replication. Origins remain fractional to preserve the anchor accurately; clamping at picture edges necessarily takes priority over preserving an off-centre anchor on zoom-out. The shipped framebuffer scale is 1.

zoomAt(lx, ly, step) takes logical coordinates and a signed step direction. level is a read-only scale getter. reset restores (1,0,0). Wheel is non-passive and prevents scrolling only while map zoom is active; zero vertical delta changes nothing. RMB mousedown steps out; contextmenu is suppressed on the canvas. No LMB zoom or double-click zoom handler is installed: wheel provides zoom-in without introducing extra cursor movements from native double-click's constituent clicks.

SCREEN/CLS reset synchronously via a wrapper on the framebuffer instance's cls method (SCREEN invokes cls). CHAIN resets synchronously via E.chain. Each display frame and each relevant mouse event also checks feature toggle, modal, module identity, and map disappearance. Capture-phase click checking happens before pointer.js. Modal open resets before the next display presentation. Pan/follow-cursor is omitted.

| SPACE long-range/galaxy, SPACESH arrow x=240 | Existing hotkey/arrow or horizontal-first map cursor step | Wheel |
| SPACE sector, SPACESH arrow x=156 | Existing hotkey/arrow or map cursor step | Wheel |
| SPACE system, marker plus A-Up Scan | Existing hotkey/arrow or map cursor step | Wheel |
| INSIDE location map, INSH arrow | Existing hotkey/arrow or map cursor step | Wheel |
| INSIDE Use arrow keys to pick provider | Existing picker row step | Wheel |
| PLBATTLE grid, PLBTSH arrow | Existing hotkey/arrow or map cursor step | Wheel |
| All other screens / modal / feature off | Existing v1.1 behavior | Disabled |

Wheel works anywhere over the canvas when a map provider is active, including over text. LMB on a blank area or current cursor cell does not zoom.

## README text for engine owner

With Map zoom enabled in Settings, use the wheel over a map screen to zoom around the pointer (1x, 1.5x, 2x, 3x, 4x); right-click zooms out one step. Left-click keeps its normal hotkey or map cursor action. Zoom resets when leaving the map, clearing the screen, changing modules, or opening an overlay. Classic mode disables map zoom.

## Open questions / integration patch

The existing display overlays (gamepad focus and text cursor) use unzoomed canvas coordinates. For overlays intended to track game content, engine owner should wrap their existing registration callbacks with ctx.save(); ctx.translate(-display.view.ox*2*display.view.scale, -display.view.oy*2*display.view.scale); ctx.scale(display.view.scale, display.view.scale); existingCallback(ctx); ctx.restore(). Apply only to input.overlay and text.drawCursor, not screen-space modal/help UI. These callbacks currently use 640x400 space and shipped atlas scale 1. No display.js changes are needed for zoom itself. Fractional pan origins preserve anchors but do not guarantee pixel-edge alignment; snapping them would trade anchor precision for strict pixel alignment. Optional cursor-follow pan remains unimplemented.

## Review fixes

This section supersedes the original wheel-only LMB policy and unconditional context-menu suppression above. No commit was made. Scope: zoom.js, zoom.test.mjs, and only the MAP_PROVIDERS gating block in pointer.js, marked `// v1.2 review Z-1`.

- **Z-1:** Each picture provider now rejects prose covering its map area even when its tracked cross/marker survives. The gate checks fully contained text cells for runs of three letters; tiles, numeric map symbols, and individual battlefield group letters remain valid. INSIDE's text picker remains a separate provider. This uses the visible framebuffer-derived screenText, rather than trusting a command panel that also survives the EQUIPING transition. SPACE list header 083CD/083D0 and INSIDE 04FAB/04FAE are inside the gated picture; SPACE sprite titles 0263B/02ADC/0389D and map commands 01B6C/030C0/03590 sit outside it. INSIDE commands 02417+ are outside its picture; PLBATTLE grid border 02486 encloses tiles, while Movement Phase 046EC and Groups In Range 0575B sit below it. No live-sprite tracking or other pointer behavior changed. A future map that intentionally prints prose inside the picture will need a narrower gate.
- **Z-2:** contextmenu now runs the reset check and suppresses the native menu only with feature enabled, live map regions, and no modal. Classic/off, non-map, and modal paths preserve native behavior.
- **Z-3:** Capture-phase LMB checks the current logical point against every pointer region. Hotkeys, arrows, selectors, and map-cell regions win. If no region claims the point on an active map screen, LMB zooms in one step around it. It prevents the event from reaching pointer.js after changing the transform, so the same event cannot generate a spurious key at its newly mapped coordinate. No double-click handler.

Updated per-screen LMB decision: all six map-provider rows in the original table keep their existing hotkey/arrow/map-cell action where a pointer region is hit; map border, cursor's own unclaimed cell, and blank unclaimed picture zoom in one step. Wheel remains available everywhere over an active map canvas. Other screens, modal, and feature-off states do not zoom on LMB.

Updated README text: On map screens, wheel zooms around the pointer; right-click zooms out. Left-click activates existing hotkeys, arrows, and map cells; left-click an unclaimed spot (such as the map border or cursor's own cell) to zoom in. Zoom resets when the map is replaced by a list or another screen, on clear/module change, and for overlays. Classic mode disables zoom and retains the native context menu.
