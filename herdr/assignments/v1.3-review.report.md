## Save slots + autosave (feature 4) — FAIL

- What works:
  - Snapshots copy all 14 station files, every extra IN/INMAP file and LOGBOOK, and copy the bytes before any await.
  - Load replaces the whole set and restores E.logbook, then restarts through ChainSignal('STARCOMM'). STARTUP 0078 re-BLOADs CHARINFO and re-reads CHARNAME, so the slot plays without a page reload.
  - Damaged or incomplete slots are rejected before anything changes.
  - Classic gives exactly the v1.1 S path: no picker, no autosave, no L.
  - Assigning `protection` is a session override that never reaches Settings.
- **F-3 overlay.js:18 (coordinator glue).** captureSave calls `E.logbook.persist()`, which writes the LOGBOOK disk file at every checkpoint: STARPORT arrival (setter), every Main-Menu wait (inkey wrapper) and every departure (E.chain).
  - CHARINFO.BAS is written only by an explicit save (STARPORT 9CF3 or Esc S). Modules keep COMMON in memory; their own BLOADs sit on dead DebugLoad paths.
  - Scenario: save at the port, fly out, win a battle, return (the arrival writes LOGBOOK with the battle), then Esc Q or close the window. The next launch has the old CHARINFO with a log book of a voyage that never happened.
  - The panels report asks for exactly the opposite: "no LOGBOOK write during observation … Quit without saving must never call persist".
  - Fix: keep the serialized journal only in the point object (`logbook: bytes of E.logbook.checkpoint()`) and write the file only in quit() and slot save.
- **F-4 slots.js:149-151.** After a slot is loaded from the title picker, the restart lands on the same STARTUP menu. Pressing `1` there opens the picker again, because `continueDisk` is only set by the "Continue current disk" row.
  - Choosing the slot again loops. The player has to know to pick "Continue current disk" to play the slot they just loaded.
  - Fix: set `continueDisk = true` (or a one-shot flag) inside load().
- Nit: overlay.js:194 and slots.js:49 validate the slot name only after the disk save is written. An empty name or "Autosave" therefore overwrites CHARINFO and then reports "Save failed".
- Nit: overlay.js:259 and :63 make a `?screen=PT-xx` dev jump (and the harness) overwrite the player's real "Autosave" slot with fixture state.
- Nit: slots.js:55 stores bytes as JSON number arrays, about 3.5 chars per byte, so roughly 380 K chars per slot. Only about 10-12 slots fit in a 5 M-char localStorage, and the UI never mentions a limit. The whole store is re-stringified at every arrival.

## Hit-chance preview (feature 8) — PASS (latent nit)

I re-derived these from the decode:

1. **PB hit chance.** Formula 06A8E: Skill*5 + f10 + aim(+50/+30/+20) − GrpToHitMod + f43 + WepAcc + 50.
   - ×0.5 for command 7 (06AAB), applied before the terrain terms.
   - Target terrain 105−35t (06AF9). Squad TerrainMod 105−35t (064C4).
   - Range +25 per band (06B40), then clamp to 10..90.
   - Aim carry-over 06346/06390 = old 37 − 3, but only when f38 = the target.
   - All of this matches combat.js:32-37.
2. **PB shots and damage.**
   - NShots = Shots×(cmd7 ? 2 : 1) (06D15), limited by loaded ammo (06D56).
   - Hit when RND×100 < pct.
   - Area span NTargets = INT(RND^0.7×size+1) with a uniform start (082B8/082D8); type 8 hits all units (082ED).
   - Damage INT(RND^.5×D+1) − armor, and negative values are dropped (083A7-083DA). E = Σk (k−a)+·[(k/D)²−((k−1)/D)²].
   - All of this matches combat.js:38-56.
3. **SB.**
   - Hit chance (056FF): f18×5 + f10 + G(rec+4) + 100/(dist+1) + aim + EnDefence×(Hull>0), where QB true = −1, so the defence is subtracted. Then ×0.5 and clamp.
   - Shots (05816): rec+6 ×(1−(cmd=7)). The limit is fuel when the gun type is > 14 (IsBeam: GunNo = type−1 > 13), otherwise rec+5.
   - Damage INT(√U×D − shield), counted only when ≥ 0 (06584/065D8), giving E = Σk (1−((k+s)/D)²)+.
   - All of this matches.

- **Latent nit combat.js:30.** `{0:18,…}`: 06924 computes `21 − 3*(t=0)` with true = −1, so skill type 0 gives field **24**, not 18. No shipped squad weapon has type 0 (items.json: 1/2/3/4 only).
