## Complete gate audit and implementation

Searched every `decode/pseudo/*.bas.md` for RuleWord$, SaveLock!, Tries!, G!(2265), rule-book/manual-word prompts. Only STARPORT contains this protection:

- 00820 loads RuleWord$; this remains intact for protected mode.
- 09AAF checks SaveLock! / G!(2265); 09AB4-09AB7 beep and return when locked.
- 09AC0 initializes Tries!; 09AC3-09BB7 clears the panel, draws the challenge, and reads the answer; 09BC9-09C81 checks length/letters.
- 09C91-09CC1 handles wrong answers and retries; 09CCC sets SaveLock! after the second miss; 09CD2 retries the challenge.
- 09CD5 is the original success label: 09CDB clears SaveLock!, 09CF3 writes CHARINFO.BAS, 09D0C-09D6D writes/closes CHARNAME, then 09D7F asks `Quit the game? (Y/N)`.

The generator injects one conditional immediately before statement 09AAF: when `rt.E.options?.protection !== true`, jump to 09CD5. This bypasses both an existing save lock and the entire challenge/retry path, and executes the unchanged successful save sequence. When protection is true the injected condition falls through to the complete v1 behavior. Regeneration reproduces the patch; flow.js was never hand-edited. No other module contains a save-lock gate or manual-word challenge.

PT-09, PT-09w, and PT-09a explicitly enable protection in their fixtures. PT-09b is registered in both exported screens and the dev table, scripts G, explicitly disables protection, and starts with SaveLock! = 1 to exercise recovery from an old protected lock.
