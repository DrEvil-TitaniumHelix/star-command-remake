## What is clickable (derive regions every click from the current screen; 320x200 logical, text cell = 8x8, row r col c -> x 8(c-1), y 8(r-1); canvas is 640x400 CSS-scaled: map clientX/Y through getBoundingClientRect)
1. Letter/digit menus: `E.input.menuItems()` already returns `{key,row,col,len}` for `X-Label` items (letters either case: send the key as printed).
2. Y/N prompts: in a line containing `(Y/N)` or `(y/n)`, the `Y`/`y` and `N`/`n` cells -> 'Y'/'N' (as printed).
3. ENTER: `Press ENTER Key`, `ENTER to accept`, any visible word `ENTER` -> `\r`. `Press SPACEBAR` -> ' '.
4. Other hotkeys printed in text: `X>` / `X)` crew/item selectors (e.g. `P>Gruber`, `1>Ortiz`, `#1`..`#9` options) -> that key; check SCREENS_INDEX for each screen's keys column and list any pattern you add.
5. Arrow crosses drawn as sprites (e.g. SPACE/SPBATTLE `SPACESH[15]`, INSIDE/PLBATTLE arrow sprites; find every arrows sprite in SCREENS_INDEX sprite columns): record the last PUT position of those sprites (wrap `E.sprites.put` in pointer.js, keep its behaviour) and map a click in the up/down/left/right arm to the arrow key (`\0H` up, `\0P` down, `\0K` left, `\0M` right).
6. Map cells where arrows move a cursor (INSIDE map, PLBATTLE grid, SPACE long-range/system cursor, IN-10 option list): a click in the map area sends ONE arrow key toward the clicked cell per click (x first or larger axis first - document). This needs the cursor position: use a per-module provider table in pointer.js (`MAP_PROVIDERS[moduleName] = (E) => ({area:{x,y,w,h}, cursor:{x,y}, cell:{w,h}})`) reading the module's state via whatever the module exposes (E.state.G, E.state.v.*, or the module instance if index/chain exposes it; read game/engine/chain.js). If a provider cannot be built without module changes, say exactly which one-line export you need in the report.
Hover: CSS cursor `pointer` over a clickable region, `default` elsewhere (the cursor must be visible in Chrome --app fullscreen). Optional: a subtle highlight via `E.display.overlays` (same style as input.overlay) - only while the mouse is the last device, never in screenshots taken without mouse moves.
When `E.input.modal` is set (Esc overlay open): call `E.input.modal.click(x, y)` (logical coords) instead and nothing else.
