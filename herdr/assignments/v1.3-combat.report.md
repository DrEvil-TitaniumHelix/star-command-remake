## Design / README text to merge

Combat aids (`combat.js`, `installCombat(E, canvas)`) read the running PLBATTLE/SPBATTLE module and COMMON without calling generated DEF helpers (those write temporary variables). Enemy hover tips cover battlefield group letters, the separate enemy-unit sprite grid, command target letters, and space enemy ship sprites / scan-map letters. They show live HP or hull/crew strength, armor, weapon, range or preferred tactic range, tactic, and living count. Gamepad highlights use the same regions; during command selection the currently targeted enemy is the gamepad focus fallback.

During the PLBATTLE command phase, move the pointer into the lower-right corner to reveal Range and Hit preview buttons. These consume no keyboard/gamepad game keys. Each aid starts closed, and is gated continuously by its Settings switch and by command-screen recognition. Range shades the current member's reach from the squad position, updating as the game advances through members: cyan corresponds to uppercase A (within reach), yellow to lowercase a (within twice reach). It uses the exact strict tolerance from PLBATTLE 17F8/183B and Groups In Range 0575B..05878, without terrain/pathfinding restrictions that the original range check does not have. Space command selection offers Hit preview only.

Hit preview displays per-shot probability, ammo/fuel-limited expected hits, and expected damage for the currently selected command/target. Wait/reload/switch/aim/psychic commands show no shots this turn. PLBATTLE uses 06864..06B69 (skill, sights, retained aim, rapid attack, target/squad terrain, reach and 10..90 clamp), 06CCA..06DAA (shot count and ammo), 082B8..082F5 (area span distribution, type 8 hits all units), and 0835D..083DA (square-root damage distribution, integer rounding, per-unit armor and discarded negative damage). Area damage is summed over the random span's living units. SPBATTLE uses 056FF..05745, 05816..058D8, and 06584..065F4, including shield absorption and signed BASIC comparisons. Estimates use current equipment, shields, and living units before intervening initiative actions, kills and critical equipment changes; they do not simulate subsequent state changes between shots. Comments cite the corresponding decode offsets and DATA_FILES mappings.

All drawing uses display.overlays and ui.js panels. The range layer follows map zoom. No framebuffer, RNG, module scalar, COMMON or save writes. Classic mode and disabled switches suppress every overlay/button. With the aids closed and no enemy hover/focus, the picture is unchanged; corner controls use fixed positioning so they do not change canvas layout. Public API: `E.combat.at(logicalX, logicalY)`, `.preview()`, `.toggleRange()`, `.togglePreview()`.

## Open questions / limits

- Coordinator must apply boot wiring and FEATURES entries above before release.
- Numerical estimates are explicitly before intervening actions/kills; repeated attacks may destroy equipment, change armor, kill targets or consume fuel, so the displayed damage is a current-state expectation, not a simulated round outcome.
- Enemy space weapons are shown as signed live damage slots; the decode's table polarity descriptions conflict in places, so the tooltip preserves the raw signed values rather than assigning potentially incorrect weapon names. Space range is labelled preferred range, not a fabricated weapon maximum.
- The range layer shows each member as that member's command is selected, matching the original Groups In Range calculation; it does not combine all members into an ambiguous single shade.
